WebSocket 是一种在单个 TCP 连接上进行全双工通信的协议，它实现了客户端与服务器之间的实时双向数据传输，解决了传统 HTTP 协议中 “请求 - 响应” 模式的局限性，非常适合需要实时数据交互的场景，如在线聊天、实时游戏、股票行情推送等。

### WebSocket 的核心特点

- **全双工通信**：客户端和服务器可以同时向对方发送数据，无需等待对方的响应，数据传输更加灵活高效。
- **持久连接**：一旦建立连接，就会保持打开状态，避免了 HTTP 协议中频繁建立和关闭连接带来的开销。
- **低延迟**：由于连接是持久的，数据传输不需要重复进行握手等过程，大大降低了通信延迟。
- **与 HTTP 兼容**：WebSocket 握手阶段使用 HTTP 协议，通常通过 80 端口（未加密）或 443 端口（加密，即 WSS）进行通信，便于穿过大多数防火墙。

### WebSocket 的工作流程

1. 握手阶段（建立连接）
   - 客户端向服务器发送一个特殊的 HTTP 请求，请求头中包含 `Upgrade: websocket` 和 `Connection: Upgrade` 等字段，表明想要将连接升级为 WebSocket 连接。
   - 服务器收到请求后，如果支持 WebSocket 协议，会返回一个 101 状态码（Switching Protocols）的响应，表示同意升级连接。同时，服务器会根据客户端提供的密钥计算出一个响应密钥，并在响应头中返回。
   - 客户端验证服务器返回的响应密钥，如果验证通过，WebSocket 连接建立成功。
2. 数据传输阶段
   - 连接建立后，客户端和服务器就可以通过这个持久连接双向传输数据了。数据可以是文本格式，也可以是二进制格式。
   - 传输的数据会被封装成帧（Frame）的形式，每个帧包含操作码、数据长度、掩码（客户端发送的数据需要掩码处理）和数据载荷等信息。
3. 关闭连接阶段
   - 当一方想要关闭连接时，会发送一个关闭帧给对方。
   - 对方收到关闭帧后，会返回一个确认关闭的帧，然后双方关闭连接。

### WebSocket 与 HTTP 的区别

| 特性     | WebSocket                              | HTTP                                          |
| -------- | -------------------------------------- | --------------------------------------------- |
| 连接方式 | 持久连接，一旦建立保持打开状态         | 非持久连接，请求 - 响应后关闭                 |
| 通信方向 | 全双工，客户端和服务器可同时发送数据   | 半双工，通常客户端请求，服务器响应            |
| 头部开销 | 连接建立后数据传输头部开销小           | 每次请求 / 响应都有较大的头部开销             |
| 适用场景 | 实时通信，如聊天、游戏、实时数据推送等 | 传统的请求 - 响应场景，如浏览网页、获取数据等 |

### WebSocket 的应用场景

- **在线聊天系统**：用户之间可以实时发送和接收消息，如各种即时通讯工具。
- **实时协作工具**：多人同时编辑文档、表格等，每个人的操作可以实时同步给其他人。
- **实时游戏**：游戏中的玩家操作、游戏状态等需要实时传输，保证游戏的流畅性和同步性。
- **实时监控系统**：如监控设备的实时数据反馈、股票行情的实时更新等。

总之，WebSocket 为实时双向通信提供了高效、低延迟的解决方案，在现代 Web 应用中有着广泛的应用。
